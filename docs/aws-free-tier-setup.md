# Free-Tier golden-validation setup (create a read-only scanner login)

Goal: a long-lived, *read-only* IAM user the scanner can authenticate as, so the
"golden" snapshot is diffable against the console. No write permissions, so Free-Tier
cost/impact exposure is zero (enumerate-only APIs). Read calls are free and do not
count against Free-Tier usage.

Console URL: sign in at `https://<your-account-id>.signin.aws.amazon.com/console`
(alias it under IAM > Account settings for a friendlier URL).

## 1. (root only) Enable MFA on the root user
IAM > Dashboard > "Activate MFA" > choose >  Authenticator app. AWS requires root MFA
before you can administer the account. (You will re-login with an MFA code.)

## 2. Create the scanner IAM user
IAM > Users > Create user:
- User name: `awsome-scanner`
- Check **"Provide user access to the AWS Management Console"** — Yes.
  Console password: autogenerated (you'll get it in the download). This is your "login".
- Uncheck nothing else. (Programmatic keys come from the same user below.)

## 3. Attach the scoped read-only policy (recommended) Or ReadOnlyAccess
Create a policy: IAM > Policies > Create policy > JSON > paste the policy below
(the exact service endpoints the scanner queries). Name it `awsome-scanner-readonly`.
Then Users > awsome-scanner > Permissions > Add permissions > Attach policies > choose
`awsome-scanner-readonly`.

> Alternative (simpler, broader): attach AWS-managed **ReadOnlyAccess** instead.
> The scanner *degrades on denial* by design, so over-broad vs scoped only changes
> how many services get enumerated vs skipped — both are safe. Start scoped; widen
> only if a walker degrades that you actually need.

  "Statement": [
    {"Effect": "Allow", "Action": ["sts:GetCallerIdentity"], "Resource": "*"},
    {"Effect": "Allow", "Action": ["ec2:Describe*"], "Resource": "*"},
    {"Effect": "Allow", "Action": [

      "elasticloadbalancingv2:DescribeListeners",
      "elasticloadbalancingv2:DescribeTargetGroups"], "Resource": "*"},
    {"Effect": "Allow", "Action": ["autoscaling:DescribeAutoScalingGroups"], "Resource": "*"},
    {"Effect": "Allow", "Action": [
      "rds:DescribeDBInstances",
      "rds:DescribeDBSubnetGroups"], "Resource": "*"},
    {"Effect": "Allow", "Action": ["elasticache:DescribeCacheClusters"], "Resource": "*"},
    {"Effect": "Allow", "Action": ["redshift:DescribeClusters"], "Resource": "*"},
    {"Effect": "Allow", "Action": [
      "es:ListDomainNames",
      "es:DescribeDomain"], "Resource": "*"},
    {"Effect": "Allow", "Action": [
      "dynamodb:ListTables",

## 4. Create programmatic access keys
Users > awsome-scanner > Security credentials > "Create access key" > **CLI**, then
save/note the Access Key ID and Secret Access Key. (Console login password is separate.)

## 5. Configure the CLI
Requires the AWS CLI (`python3 -m pip install awscli` if absent):

```sh
aws configure --profile awsome
# AWS Access Key ID:     <paste key id>
# AWS Secret Access Key:<paste secret>
# Default region name:  us-east-1
# Default output:       json
```

Verify:
```sh
mise x -- bash -lc 'AWS_PROFILE=awsome aws sts get-caller-identity'
```

## 6. Golden scan (single region, read-only)
```sh
make scan-real        # uses profile "awsome", region us-east-1 by default
open snapshots/$(ls -t snapshots | head -1)/summary.json
```
To scan everything the account enables: `make scan-real REGIONS=` — but start with one
region; the account likely has only `us-east-1` active on Free Tier anyway.

## Hygiene
- The access keys live in `~/.aws/credentials` (never in this repo).
- To revoke later: IAM > Users > awsome-scanner > Security credentials > Deactivate/Delete
  keys, and/or Delete the user. You can also delete the policy to instantly break all access.
- If a walker shows as degraded, that's expected for permissions the policy omits —
  widen only what you genuinely want validated.
